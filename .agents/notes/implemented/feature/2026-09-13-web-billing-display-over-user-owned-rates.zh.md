# Agent Note: Web billing display over user-owned model rates

Status: implemented

[English](2026-09-13-web-billing-display-over-user-owned-rates.md) | 中文

## 问题

Web 图形界面报告了会话消耗了什么，却没有报告它花了多少钱。composer 下方的 token 胶囊与「本轮用量」对话框给出轮次、步骤、缓存命中比例与 token 分桶，这些全都是提供方上报的；没有任何东西把这些分桶变成金额，而这些提供方同时暴露的 DeepSeek 账户余额更是没有任何界面。

有两个事实使它成为一个插件而非一次主循环改动。定价是用户自有的配置：harness 一无所知的一条路由——网关、自托管服务、转售方——只能由运维者自己填写的数字来计价。而一次会话会混用路由：同一段对话既跑在官方 DeepSeek 提供方上，也跑在任何其他已配置的提供方上，因此单一的会话合计必须按计费它的那条路由为每一段计价，而不是套用一个混合单价。

## Decision

`@deepseek-ai/dsh-client-ui-billing` 是一个双面包：Host 半边拥有 `ui-billing` settings 命名空间，并在其中缓存一份 DeepSeek 账户余额；浏览器半边在该值之上渲染三个界面。

### 命名空间就是全部约定

`ui-billing` 保存 `models`（按 `provider/model` 为键的单价行，每行含「元 / 百万 tokens」的 `cacheHit`、`cacheMiss` 与 `output`）、`currency`（所有费用显示所用的币种代码），以及两个 Host 所有的字段：`cache`，Host 最近一次读到的余额，和 `cacheError`，最近一次读取失败的原因。单价经由普通的 settings Remote 写入；余额由 Host 通过自己的 scope 句柄写入。因此两个平面读取同一个值，谁都不需要自己的 Remote。

`Currency` 是配置而不是常量，因为 DeepSeek 端点报告的是账户实际持有的币种，且可能报告多种；页面按配置的币种计价与标注，Host 读取在账户提供选择时优先该币种。以另一种币种结算的部署只需改一个 settings 字段，而不是代码常量。

### 两套折叠，因为两个界面掌握的证据不同

会话合计累积 `tokenUsage` 投影：它是整份持久日志上的运行总量，因此每次观察到的增长恰好就是某条路由被计费的部分；为每次增长记录一段，既能正确计价会话中途的模型切换，又不必保留任何按路由的历史。编辑单价会重算每一段，因为该折叠保留的是分桶而不是金额。

每轮费用行从持久的 turn-tail 账目出发——与官方「本轮用量」对话框所显示的同一个数字——并按已加载尝试中读到的路由拆分它。被重试的尝试会让合计大于存活的样本；该剩余部分按最后一条路由的单价计入，这使计价总额与提供方上报的 tokens 保持一致，即便拆分本身是近似的。

### Host 读取是本包唯一的请求

这里不发起任何模型请求，也不追加任何会话事件。Host 每次读取时通过 credentials seam 解析 API key，调用一次 `GET /user/balance`，并把结果写回；刷新链通过 timer 服务重新排期，并随插件 fiber 一起停止。读取失败会把上一份快照连同原因一起保留，因此陈旧的金额仍然以「陈旧」的姿态可读。key 按运维者自己的配置值处理；格式非法的引用是 seam 该拒绝的事，不是本包的事。seam 是必需注入而不是可选读取：首次读取若早于凭据文档载入，就会把「运维者没有存过 key」当作结论上报；未挂载凭据存储的组合仍以进程环境作为回落。

### 注册

三个界面，卸载时各自还原：`settings.section`（计费页，列出部署可配置的每个提供方，并为该提供方自身 settings 配置声明的每个模型给出一行，另有为任何配置都没有命名的路由准备的手工入口）、`conversation.composer.dock`（本会话费用胶囊与余额胶囊，排在官方统计行之后），以及 `conversation.chat.turnTail` 链（每轮费用行，链优先级低于官方交付文件条目，因此有文件的轮次仍保留其文件行）。

composer dock 是每个注册项一行的居中列，而官方那一行居中的是一组宽度随所读数字变化的胶囊。因此本行按官方行的精确高度上提，并让自身内容从共享盒子的左端起算一个固定比例——盒子在 680px 封顶时取 41.2%——从而避开官方那组胶囊可能达到的最宽读数。仅仅「重合」是不够的：两行会互相压字。

settings 命名空间与本包的文案字典分开命名（`ui-billing` 与 `billing`）。两者共用一个标识符会把 scope 绑到字典上，读起来就像一个未注册的命名空间：Host 明明在提供正确取值，而每个界面都渲染自己的「不可用」状态。

## Alternatives considered

**改动官方统计胶囊的核心代码。** 把费用行扩展进 ui-chat 自己的 `StatsPills` 与 `TurnUsagePanel`，本可以把数字放在需求点名的确切位置，但那样一来，产品意义上的金额语义——用户自有的单价、缓存的账户余额——就成了一个职责为呈现提供方上报用量的包的一部分。一个注册在它们旁边的插件保持了这份分离，并且可以被组合移除。

**为费用增设一个 Host 投影单元。** 在 Host 计算费用并作为 `sessionProjections` 的键发布，可以把算术移出浏览器，但投影单元必须是持久日志的确定性折叠，而单价是不在该日志中的用户配置。投影只能承载 token 分桶，而浏览器已经能从 `tokenUsage` 累积这些分桶；新增的单元什么都换不来。

**为余额增设一个 `Typert` Remote。** Host Remote 方法本会是规范的客户端到主机调用，但它需要一份新的生成产物和一个客户端命名空间，只为页面读取一次并显示的一个数字。把读取缓存进 settings 命名空间，复用了单价已经在走的传输，也让余额对一份普通文档编辑可见。

**峰谷时段单价表。** 提供方的错峰折扣在固定每日时段内是半价，因此表格式的单价本可以更贴近它。它被否决，是因为折叠没有逐分桶的时间戳：分桶以每次尝试的聚合形式到达，而会话合计根本不含时间，所以时段表只能为那些真实时间按步骤记录着的 tokens 猜一个时段。三个静态单价恰好陈述了已知的事实；想要这份折扣的运维者可以填入错峰数字。

## Consequences

**换来的。** 页面是单价唯一的所在，而没有单价的路由不进入任何合计：胶囊显示短横线，对话框点名该路由，而不是显示一个当前配置无法支撑的数字。中途切换提供方的会话能正确地为每一段计价。余额始终是 DeepSeek 账户的余额，无论当前轮次跑在哪个提供方上，这正是让花销与 API 唯一能报告的那个账户可比的前提。

**代价。** 一条单价行是一条路由，而不是一次尝试：某个轮次的尝试落在已加载窗口之外时，该轮次按持久账目点名的路由计价，剩余部分计在最后一条上，因此一次被重试的轮次在两条路由之间的拆分是近似的，尽管总额不是。缓存写入按未缓存输入计费，这与 DeepSeek 适配器上报用量的方式一致，但不适用于把写入上报到独立分桶的提供方。这里没有任何东西把计算出的总额与提供方账单对账；两次读取之间余额的变动是唯一的外部检验。

**验证。** `packages/client/ui-billing/tests/cost.spec.ts` 钉住各折叠与金额格式；`tests/host.host.spec.ts` 在内存 settings provider 之上挂载 Host 半边，钉住命名空间、缓存读取、读取失败路径与卸载；`tests/billing.client.spec.tsx` 面向真实 `SlotRegistry` 驱动三个组件界面与插件的注册。
