# Agent Note: Web billing display over user-owned model rates

Status: implemented

[English](2026-09-13-web-billing-display-over-user-owned-rates.md) | 中文

## 问题

Web 图形界面报告了会话消耗了什么，却没有报告它花了多少钱。composer 下方的 token 胶囊与「本轮用量」对话框给出轮次、步骤、缓存命中比例与 token 分桶，这些全都是提供方上报的；没有任何东西把这些分桶变成金额，而这些提供方同时暴露的 DeepSeek 账户余额更是没有任何界面。

有两个事实使它成为一个插件而非一次主循环改动。定价是用户自有的配置：harness 一无所知的一条路由——网关、自托管服务、转售方——只能由运维者自己填写的数字来计价。而一次会话会混用路由：同一段对话既跑在官方 DeepSeek 提供方上，也跑在任何其他已配置的提供方上，因此单一的会话合计必须按计费它的那条路由为每一段计价，而不是套用一个混合单价。

## Decision

`@deepseek-ai/dsh-client-ui-billing` 是一个双面包：Host 半边拥有 `ui-billing` settings 命名空间，并在其中缓存两项来自提供方的读取——DeepSeek 账户余额与公布的价目表；浏览器半边在该值之上渲染三个界面。

### 命名空间就是全部约定

`ui-billing` 保存 `models`（按 `provider/model` 为键的单价行，每行含高峰时段的「元 / 百万 tokens」`cacheHit`、`cacheMiss` 与 `output`，以及可选的 `offPeak` 一档）、`currency`（所有费用显示所用的币种代码），以及四个 Host 所有的字段：`cache` 与 `official`，Host 最近一次读到的余额与价目表，和 `cacheError` 与 `officialError`，两者各自最近一次读取失败的原因。单价经由普通的 settings Remote 写入；两项读取都由 Host 通过自己的 scope 句柄写入。因此两个平面读取同一个值，谁都不需要自己的 Remote。

单价行里平铺的三个字段就是高峰一档，`offPeak` 是第二档，因为提供方可能公布一个价格，也可能公布两个：该档缺失即表示这条路由全天同价，正是只公布一个价格的提供方的情形；这也让本包引入时段之前写下的每一行仍然有效。

`Currency` 是配置而不是常量，因为 DeepSeek 端点报告的是账户实际持有的币种，且可能报告多种；页面按配置的币种计价与标注，Host 读取在账户提供选择时优先该币种。以另一种币种结算的部署只需改一个 settings 字段，而不是代码常量。价格读取受同一个字段约束：公布页用它自己语言版本的币种陈述数字，因此另一种币种的表格会被拒绝并同时点名两个代码，而不是混进错误币种的数字里。

### 价格时段

公布单价不是每天一个数字。DeepSeek 对高峰时段（北京时间周一至周五 9:00–12:00、14:00–18:00，英文版以 UTC 陈述）按公布价计费，其余时间按半价，因此跨越边界的会话会吃到两个单价。时段规则是提供方公布的时刻表，而不是部署的选择，因此 `priceWindowAt` 以北京时间把它固定下来；按另一套日历结算的部署改为覆盖受影响路由的单价。

于是每一段被计费的部分都带上它发生的时刻，折叠据此选择当时生效的那一档，而不是去猜一张时刻表。会话折叠给运行总量的每次观察到的增长打上观察时刻，也就是提供方在这些 tokens 产生时正在计价的时段。轮次折叠给每条尝试打上它自己那条结算消息所带的时间；没有时间的尝试不算证据，正如没有路由的尝试不算证据。存量行没有 `offPeak` 一档的路由不按时段拆分，因为两档数字本就相同。

因此两档是文档对**每条**路由的词汇，而不只是对今天公布两档的那个提供方：schema 无从知道下一个按时段计价的提供方是谁。默认只有官方卡片给出两档——只公布一个价格的提供方全天同价，两行空字段等于问了一个它的提供方并不存在的问题。其它路由一旦持有某一档（存过的，或公布表格陈述的），或被页面要求加上，就多出第二行；这正是「某个提供方开始按时段计价、而别处还不知道」时的开口。

### 两套折叠，因为两个界面掌握的证据不同

会话合计累积 `tokenUsage` 投影：它是整份持久日志上的运行总量，因此每次观察到的增长恰好就是某条路由被计费的部分；为每次增长记录一段，既能正确计价会话中途的模型切换，又不必保留任何按路由的历史。编辑单价会重算每一段，因为该折叠保留的是分桶而不是金额。

每轮费用行从持久的 turn-tail 账目出发——与官方「本轮用量」对话框所显示的同一个数字——并按已加载尝试中读到的路由拆分它。被重试的尝试会让合计大于存活的样本；该剩余部分按最后一条路由的单价计入，这使计价总额与提供方上报的 tokens 保持一致，即便拆分本身是近似的。

### Host 读取是本包仅有的请求

这里不发起任何模型请求，也不追加任何会话事件。Host 每次读取时通过 credentials seam 解析 API key，调用一次 `GET /user/balance`，并把结果写回；刷新链通过 timer 服务重新排期，并随插件 fiber 一起停止。读取失败会把上一份快照连同**结构化原因**一起保留——没有 key、HTTP 状态、传输失败、响应无法解析——因为读取归 Host 所有而文案归浏览器所有：原因以「种类 + 句子所需的取值」跨过这条边界，中英文界面因此各自用自己的语言陈述，而不是把一句英文拼进翻译过的模板，只有人无法翻译的技术细节保持原样附在后面。key 按运维者自己的配置值处理；格式非法的引用是 seam 该拒绝的事，不是本包的事。seam 是必需注入而不是可选读取：首次读取若早于凭据文档载入，就会把「运维者没有存过 key」当作结论上报；存储里没有该引用对应取值时，进程环境是回落。读取本身接收一个 key 解析器而不是 context，凭据 seam 因此归插件体所有，读取不触碰任何服务。

第二项读取回答的是另一个问题：提供方现在收多少钱。DeepSeek 没有价格接口——它的 API 只有补全、文件、一份只有 id 的模型列表和余额——因此公布价页面是价格唯一可机读的表述，`pricingUrl` 指向与 `currency` 匹配的那个语言版本。解析器读那张页面服务端渲染的表格：每个模型一列，每个时段一对行，单位后缀标明币种。它会拒绝：没有任何模型名的表格、只公布了单一时段的表格、同时陈述两种币种的表格、以及数值不带单位的表格；每次拒绝都像余额失败那样被记录下来——一个种类加上句子所需的取值——因此页面改版的代价是沿用一份过时的默认价，而不是算错账单。取页面走的是本部署自己的路径：读取接收一个取页函数，由插件体从可选的 `web` 服务解析而来，解析器因此保持为对 markup 的纯函数，而没有挂载网页读取能力的部署得到的是「什么都没读到」的具名原因，而不是一次传输失败。读取尚未成功时，出厂快照继续给官方路由计价；两条链各自排期、结算与卸载。

公布价很少变动，因此这次读取的间隔很长，且以「被要求」而非轮询为主：默认十五天（`pricingRefreshIntervalMs`；`0` 只读一次、之后不再排期），启动时若存量表格仍在间隔之内，就只等待它剩余的时间而不再读一次——这正是重启不产生请求的原因——而计费页的「立即读取」控件随时可以要求读一次。每次结算都从自身重新排期，并替换掉尚未触发的那个定时器，所以页面要求的读取是把自动那次往后推，而不是再加一个定时器。这个请求以 settings 写入的形式传递：浏览器读不了那张文档页，本包也没有可调用的 Remote 命名空间；客户端把请求时刻写进 `officialRequest`，Host 监听自己的命名空间，并在该次读取结算时清掉该字段，页面据此显示读取中。`officialRequest` 「不存在」与「为 null」可以互换——schemastery schema 里的联合类型两者都不会写进文档——因此每个读取方都把它当作 nullish。

两项读取都必须由 Host 完成，因为页面自己也拿不到这两件事实：余额需要 Host 通过凭据 seam 持有的 API key，而价格页对浏览器 fetch 没有 CORS 授权。用本部署已经挂载的能力去读页面，可以把取回路径收敛成一条——超时、重定向策略、正文上限都是它既有的——而不是再加一个本包自己的 HTTP 客户端；正文被截断时直接拒绝，因为被截短的表格读起来会像是一个没有公布价格的页面。

### 注册

三个界面，卸载时各自还原：`settings.section`（计费页）、`conversation.composer.stats`（本会话费用与余额两个数字）、以及 `conversation.chat.turn-stats`（每轮费用胶囊）。

composer 这两个数字属于 ui-chat 已经拥有的那一行，因此由 ui-chat 声明这个洞、并由它自己的统计行渲染：`conversation.composer.stats` 是 `conversation.composer.dock` 那一行的 session 作用域 `list` 子槽，渲染出的子节点直接吃这一行自己的 12px 间距，整行每一对之间的距离因此一致。早先的做法——再造一行、按官方行高度上提、再偏移到官方胶囊之后——只能去猜一组宽度随数字变化的居中内容会在哪里结束，猜错时就压字；随后那条由该行画在贡献之前的分隔线，又在一条本就宽度受限的行上花掉 13px，去隔开行自身的间距本来就已经隔开的两个数字。

每轮费用胶囊挂在轮次自己的操作条上，而这条操作条现在会为「在任何定稿文本之前就被中断」的轮次渲染。此前这条分支在操作条存在之前就返回了，于是被中断的轮次既没有官方用量数字、也没有任何东西挂在旁边；在一个用户总在中途打断的会话里，这就等于完全不显示费用。确实无内容可展示的轮次（没有收尾消息、没有贡献、没有账目，且本回合内还有更晚的证据）仍然什么都不渲染。

这些数字位于操作条**内部**，而不是它上方的那条 tail 链上——因为链只会选出一个条目：凡是官方交付文件条目认领的轮次，费用胶囊都会无声消失。`conversation.chat.turn-stats` 是 `turn-tail` 这个 Chat 节点的 session 作用域 `list` 子槽，由 `TurnTailNodeView` 渲染在官方「用量」「用时」之后，行本身把落在末尾的这个数字按胶囊串内部同样的 6px 回退并入其中。

胶囊以轮次尾部的持久账目计价，并按已加载尝试**实际被计费的那条路由**归属；账目缺失时干脆不显示数字：会话投影是整场会话的运行总量，把它读成某一轮的费用，就等于把整场会话印在这一行上。归属需要每次尝试被计费的路由，而 Chat 折叠现在把它保留在定稿的 `assistant-step` 节点上——`finalNode.provenance`，也就是同类 Definition 早已记录的持久 `message.source`——因此中途换过模型的轮次真正做到了按路由计价，而不是根本拆不开。账目点了多条路由、而这些尝试一条都不在窗口里时，拆分无从谈起：此时不产出任何计价行，而不是把整份合计在每条路由上各记一遍（那会把该轮计费多次）；对话框改为点名这些无法归属的路由。只点名一条路由的轮次仍然精确计价，因为每一次尝试都跑在那里。

计费页跟随官方「模型」页的做法：用户层配置过的、适配器当前正在服务的、或部署层 profile 里带模型的提供方（官方提供方属于最后一种）各一张卡片，模型列表收在该卡片自己的编辑控件之后。三者都不占的目录条目没有可定价的东西，就不贡献卡片。

所有 ctx 读取都归 apply 闭包。组件拿到的是命名空间快照的 `useBilling` 选择器钩子与已加载分组的 `useBillingGroups` 钩子（两者都由渲染器从 `hooks` 舱里的裸 source 绑定），以及 `routeGroups`、`saveRate`、`clearRate` 三个普通回调。目录的失效信号在插件里订阅，而且在页面开口之前什么都不加载——因此挂载本插件本身不发出任何请求。

行的拥有者事实到达条目时是**摊平**的，绝不嵌在 `owner` 之下：渲染器交给组件的是 `{...ownerProps, ...}`，因此每轮胶囊直接读 `turn`，与官方交付文件条目直接读 `openFile` 是同一种读法。早先按 `props.owner` 读，会让胶囊永久消失且不报任何错——本包自己的 spec 手喂了那个嵌套形状，因此看不见这一点。每个组件都按槽的几份份额声明 props——`PropsRuntime`、本插件的 `InjectFace`、`PropsLocale`——而不是把成员重抄一遍；框架日后新增的座位无需在这里改动就能到达组件。

settings 命名空间与本包的文案字典分开命名（`ui-billing` 与 `billing`）。两者共用一个标识符会把 scope 绑到字典上，读起来就像一个未注册的命名空间：Host 明明在提供正确取值，而每个界面都渲染自己的「不可用」状态。

## Alternatives considered

**改动官方统计胶囊的核心代码。** 把费用行扩展进 ui-chat 自己的 `StatsPills` 与 `TurnUsagePanel`，本可以把数字放在需求点名的确切位置，但那样一来，产品意义上的金额语义——用户自有的单价、缓存的账户余额——就成了一个职责为呈现提供方上报用量的包的一部分。一个注册在它们旁边的插件保持了这份分离，并且可以被组合移除。

**由单价行自带时段表。** 一行本可以自己带着时段规则——在固定每日区间内半价——让一行就描述一整天。它被否决，是因为这条规则属于提供方而不是部署：换一个时段不同、或根本没有折扣的提供方，就得各写一份时刻表，而且同一提供方的每一行都要重复它。页面编辑的是价格档，文档里存的也是价格档；时刻表始终只是每次计费自身时刻的纯函数。这个时刻正是一开始否决「表格式单价」的症结——分桶以每次尝试的聚合形式到达，自身不含时间——而它现在由定稿助手节点的时间（对尝试）与观察时钟（对会话总量的增长）解决。

**为费用增设一个 Host 投影单元。** 在 Host 计算费用并作为 `sessionProjections` 的键发布，可以把算术移出浏览器，但投影单元必须是持久日志的确定性折叠，而单价是不在该日志中的用户配置。投影只能承载 token 分桶，而浏览器已经能从 `tokenUsage` 累积这些分桶；新增的单元什么都换不来。

**为余额增设一个 `Typert` Remote。** Host Remote 方法本会是规范的客户端到主机调用，但它需要一份新的生成产物和一个客户端命名空间，只为页面读取一次并显示的一个数字。把读取缓存进 settings 命名空间，复用了单价已经在走的传输，也让余额对一份普通文档编辑可见。

## Consequences

**换来的。** 页面是单价唯一的所在，而没有单价的路由不进入任何合计：胶囊显示短横线，对话框点名该路由，而不是显示一个当前配置无法支撑的数字。官方提供方的路由自带公布价默认值——配置过官方模型的用户，此前必须先照着官方价目表敲三个数字，会话合计才有意义；存过的一行覆盖默认值，页面把它显示为输入框占位符并带「默认单价」标记，清除该行即恢复默认值。这些默认值跟随提供方：Host 每天读取公布页，因此调价无需改代码就能到达胶囊；跨越高峰边界的会话会分别吃两档，而不是一个混合价。中途切换提供方的会话能正确地为每一段计价。余额始终是 DeepSeek 账户的余额，无论当前轮次跑在哪个提供方上，这正是让花销与 API 唯一能报告的那个账户可比的前提。

**代价。** 一条单价行是一次计费，而不是一次尝试：在另一条路由上重试过的轮次，只按已加载窗口里存活下来的那些尝试计费，剩余部分计在最后一条上，因此一次被重试的轮次在两条路由之间的拆分是近似的，尽管总额不是。账目不完整的轮次——或账目点了多条路由、尝试却一条都不在窗口里的轮次——干脆不显示数字，因此一个旧轮次可能在它的回答仍在屏幕上时读起来像是没有花费。会话合计从浏览器**第一次看到**运行总量起归属：日志在这之前计费的一切都按当时生效的那条路由与那个时段计价，因此中途刷新页面会把整份合计重读成一条路由、一个价档。跨越价格边界的一段按它自身时刻生效的那一档计费，对一次跨越边界的长尝试来说就是它结束时的那一档。composer 的两个数字都要等官方统计行出现，所以全新会话在第一个轮次之前看不到余额。公布价来自一张文档页面而不是价格源，因为提供方没有价格源：读到的表格无法识别、或它按另一种币种计价时，继续给出厂快照计价，并在页面上说明；没有挂载网页读取能力的部署则根本读不到那张页面。一行按字段逐个写入，因此没被碰过的字段保留文档中原有的取值，而不是变成零。缓存写入按未缓存输入计费，这与 DeepSeek 适配器上报用量的方式一致，但不适用于把写入上报到独立分桶的提供方。这里没有任何东西把计算出的总额与提供方账单对账；两次读取之间余额的变动是唯一的外部检验。

**验证。** `packages/client/ui-billing/tests/cost.client.spec.ts` 钉住两套折叠、每个边界与周末的时段判定、金额格式与路由发现；`tests/official-rates.client.spec.tsx` 钉住公布的两档、存量行 > 读取到的表格 > 出厂快照的优先级，以及两个时段各自的会话计价；`tests/published-prices.host.spec.ts` 解析两个语言版本实际录下的价格表，钉住币种拒绝与「交给它的取页路径」上的每一种读取失败，包括正文被截断与完全没有取页路径；`tests/host.host.spec.ts` 在内存 settings provider 与「持有单个桩提供方的真实 web 能力」之侧挂载 Host 半边，钉住命名空间、两项缓存读取、等待凭据存储、两条失败路径、没有能力可用的那次读取、两个刷新间隔、存量表格年龄决定「等待」与「该读」的两种情形、页面写入的请求及其清除、以及同一个请求重复写入只服务一次；`tests/billing.client.spec.tsx` 面向真实 `SlotRegistry` 驱动三个组件界面与插件的注册，其中包括「轮次自身账目缺失时不给数字」「多条路由且无已加载尝试时拒绝计价」「按时段的单价字段与占位符」「按需展开第二档的路由」与「已存第二档时无需展开即显示两档」、`Read now` 控件的读取中与被拒两种状态，以及一次保存所产生的 settings 操作；`packages/client/ui-chat/tests/conversation-node-definitions.client.spec.ts` 钉住定稿助手节点上的被计费路由与结算时间，`tests/turn-tail-row.client.spec.tsx` 钉住「已完成轮次」行的两种形态与尾部数字在行内的位置，`tests/chat-stats.client.spec.tsx` 钉住 composer 贡献是那一行自己的 flex 子项，`tests/turn-tail-spacing.client.spec.ts` 钉住两条行的间距契约。
